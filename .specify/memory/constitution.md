# Calender App J123 Constitution

## Core Principles

### I. 日本語実装 (Japanese Implementation)

すべてのコード、コメント、ドキュメント、エラーメッセージ、ログは日本語で記述する。変数名、関数名、クラス名は英語を使用するが、コメントとドキュメントは日本語で記述する。ユーザー向けのメッセージ、UI要素、設定ファイルの説明は日本語で提供する。

**根拠**: プロジェクトの一貫性と保守性を確保し、日本語話者による開発と運用を容易にする。

### II. ローカル実行可能 (Local Executability)

アプリケーションは外部サービスへの依存を最小限に抑え、ローカル環境で完全に実行可能でなければならない。データベース、ファイルシステム、設定ファイルはすべてローカルに保存され、インターネット接続なしで動作する。依存関係のインストールと実行に必要な手順は明確に文書化され、単一のコマンドまたはスクリプトで起動できる。

**根拠**: 開発環境の一貫性、オフライン動作の保証、デプロイの簡素化を実現する。

### III. テスト駆動開発 (Test-Driven Development) (必須)

TDDを厳格に遵守する。テストを先に記述し、ユーザー承認を得てから実装を開始する。Red-Green-Refactorサイクルを厳格に適用する。すべての機能には対応するテストが存在し、テストが失敗する状態から実装を開始する。

**根拠**: コードの品質と信頼性を保証し、リファクタリングの安全性を確保する。

### IV. 統合テスト (Integration Testing)

新規ライブラリのコントラクトテスト、コントラクト変更、サービス間通信、共有スキーマの変更には統合テストが必須である。各ユーザーストーリーは独立してテスト可能でなければならない。

**根拠**: システム全体の動作を保証し、回帰を防止する。

### V. シンプリシティ (Simplicity)

YAGNI原則に従い、必要最小限の機能から開始する。複雑さは正当化されなければならない。シンプルな解決策を優先し、過度な抽象化やパターンの適用を避ける。

**根拠**: 保守性と理解しやすさを確保し、開発速度を向上させる。

## ローカル実行要件 (Local Execution Requirements)

### データストレージ

- データベースはローカルファイルベース（SQLite等）またはローカルファイルシステムを使用する
- 外部データベースサービス（クラウドDB等）への依存は禁止
- データのバックアップと復元はローカルファイル操作で行えること

### 依存関係管理

- すべての依存関係は標準的なパッケージマネージャー（npm, pip, cargo等）で管理される
- 外部APIやクラウドサービスへの依存は最小限に抑える
- 必須の外部依存がある場合は、モックまたはスタブで代替可能にすること

### 実行環境

- アプリケーションは単一のコマンドまたはスクリプトで起動できること
- 環境変数や設定ファイルによる設定変更が可能であること
- 開発環境と本番環境の差異を最小限に抑えること

## 開発ワークフロー (Development Workflow)

### コードレビュー

すべてのプルリクエストは憲法の遵守を確認するレビューを経る。複雑さの追加は正当化されなければならない。

### 品質ゲート

- すべてのテストが通過すること
- リンターとフォーマッターのチェックを通過すること
- ローカル環境で正常に動作すること

### ドキュメント

- README.mdにローカル実行手順を明記すること
- 各機能の使用方法を日本語で文書化すること
- 環境構築手順を明確に記述すること

## Governance

この憲法はすべての開発実践に優先する。修正には以下の手順を踏む：

1. 修正案を文書化し、理由を明確にする
2. 影響を受けるテンプレートファイルを更新する
3. バージョン番号を適切に更新する（セマンティックバージョニング）
4. Sync Impact Reportを更新する

すべてのPR/レビューは憲法への準拠を確認しなければならない。複雑さは正当化されなければならない。

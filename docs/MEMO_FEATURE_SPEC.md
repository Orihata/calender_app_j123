# ひとことメモ機能 - 仕様書

**機能**: スケジュール画像のカードに「ひとことメモ」を追加する機能  
**バージョン**: 1.1.2  
**作成日**: 2026-01-09  
**更新日**: 2026-01-13  
**ステータス**: ✅ 実装完了

---

## 概要

ユーザーが観戦予定（AttendancePlan）に対して「ひとことメモ」を追加できる機能を実装します。  
メモはスケジュール画像（待受画面用画像）のカード下部に別色のエリアとして表示されます。

---

## ✅ 確定仕様

### 1. データモデル

#### 1.1 AttendancePlanモデルの拡張

**追加フィールド**:
- `memo` (string | null, optional): ひとことメモのテキスト
  - 最大文字数: 制限なし（ただし、UIで入力制限を設けることを推奨）
  - 空文字列の場合は`null`として保存
  - デフォルト値: `null`

**変更後のAttendancePlan構造**:
```javascript
{
  id: string,
  matchId: string,
  category: 'venue' | 'broadcast',
  memo: string | null,  // 追加
  createdAt: string,
  updatedAt: string
}
```

#### 1.2 データ永続化

- **保存場所**: localStorage（既存の`attendancePlans`キーに含まれる）
- **データ削除**: AttendancePlanが削除されると、メモも不可逆に削除される
  - メモはAttendancePlanに紐づいているため、自動的に削除される
  - 特別な削除処理は不要

---

### 2. UI仕様

#### 2.1 メモ入力・編集

**表示場所**: 観戦予定一覧画面（`AttendanceList`コンポーネント）

**入力方法**:
- 各観戦予定カードにメモ入力欄を追加
- テキスト入力フィールドまたはテキストエリアを使用
- リアルタイム保存（入力と同時に保存）

**入力制限**:
- 最大文字数: **20文字**
- 改行は許可しない（1行のみ）
- 空白のみの入力は`null`として保存

**表示モード**:
- **閲覧モード**: メモをテキストとして表示（メモがない場合は非表示）
- **編集モード**: テキストボックスとして編集可能
  - 既存の「閲覧/編集」モードトグルボタンと連動
  - プレースホルダー: "ひとことメモを入力...（最大20文字）"

#### 2.2 メモ削除

- メモ入力欄を空にして保存すると、メモが削除される（`null`として保存）

---

### 3. カードレイアウト仕様

#### 3.1 メモエリアの配置

**位置**: カード下部にくっつけて配置

**レイアウト構成**:
```
┌─────────────────────────┐
│ カード本体（既存）       │
│ （グラデーション背景）    │
├─────────────────────────┤
│ メモエリア（別色背景）   │ ← 追加
└─────────────────────────┘
```

**エリアサイズ**:
- 高さ: **20px**（固定）
- 幅: カード幅と同じ（340px）
- 角丸: 下部のみ角丸（8px）、上部は直線

#### 3.2 メモテキストのスタイル

**フォント設定**（会場と同一）:
- フォントサイズ: **32px**（元のサイズ）→ **16px**（スケーリング後、340x135px基準）
- フォントウェイト: **500**
- フォントファミリー: **Noto Serif JP**（Version 1.1.2で変更）

**テキスト表示**:
- 位置: メモエリアの左側、上下中央揃え
- 左マージン: **15px**（カードのパディングと同様）
- 最大幅: カード幅 - 左マージン - 右マージン（約310px）
- 1行で収まらない場合: **末尾をtruncate**（`...`を表示）
- テキストのオーバーフロー処理: `text-overflow: ellipsis`, `white-space: nowrap`, `overflow: hidden`

**文字色**:
- **統一文字色**: 白（`#FFFFFF`）
  - 現地観戦・放送視聴に関わらず統一
  - 背景色とのコントラストを確保
- メモがない場合: 文字を表示しない（メモエリアは空白）

#### 3.3 メモエリアの背景色

**現在のカード背景色（実装を確認）**:
- 現地観戦（venue）: 
  - グラデーション開始: `#F0F7FC`
  - グラデーション終了: `#E8F2F8`
- 放送視聴（broadcast）:
  - グラデーション開始: `#E8F5E9`
  - グラデーション終了: `#C8E6C9`

**メモエリアの背景色**（Version 1.1.2で統一）:
- **統一背景色**: 紺色（`#2A456F`）
  - 現地観戦・放送視聴に関わらず統一
  - メモの有無に関わらず常に表示
- カード本体との視覚的な区別を明確にする
- メモエリアの背景色は単色（グラデーションなし）
- メモエリアとカード本体の境界線は不要（自然なつながり）

---

### 4. カードサイズの調整

#### 4.1 メモエリアを含むカードの高さ

**現在のカード高さ**: 135px  
**メモエリアの高さ**: 20px  
**新しいカード高さ**: **155px**（メモがある場合）

**計算方法**:
```javascript
const CARD_HEIGHT = 135 // 既存のカード高さ
const MEMO_AREA_HEIGHT = 20 // メモエリアの高さ
const CARD_HEIGHT_WITH_MEMO = CARD_HEIGHT + MEMO_AREA_HEIGHT // 155px
```

**メモがない場合**: 135px（既存と同じ）

#### 4.2 カード配置への影響

**配置計算の方法**:
- メモがあるカードとないカードが混在する場合、**すべてのカードを最大高さ（155px）で配置**する
- これにより、カードの配置が統一され、視覚的な整列が保たれる

**実装方法**:
1. カード枚数に応じて行数`n`を計算（既存のロジック）
2. カード高さは常に`155px`（メモエリアを含む）として計算
3. メモがないカードは、メモエリア部分を空白（またはカード背景色）として描画
4. カード間のマージン計算は変更しない

**代替案（非推奨）**:
- メモがない場合はメモエリアを表示しない（カード高さ135px）
  - この場合、カードの高さが不統一になり、配置が崩れる可能性がある

### 5. 実装詳細

#### 5.1 データモデルの変更

**ファイル**: `src/models/AttendancePlan.js`

```javascript
constructor(data) {
  this.id = data.id
  this.matchId = data.matchId
  this.category = data.category || 'venue'
  this.memo = data.memo || null  // 追加
  this.createdAt = data.createdAt
  this.updatedAt = data.updatedAt
}

toJSON() {
  return {
    id: this.id,
    matchId: this.matchId,
    category: this.category,
    memo: this.memo,  // 追加
    createdAt: this.createdAt,
    updatedAt: this.updatedAt
  }
}
```

#### 5.2 画像生成の変更

**ファイル**: `src/services/imageExportService.js`

**変更点**:
1. `drawCard`関数にメモ描画処理を追加
2. メモがある場合のみメモエリアを描画
3. カード高さを動的に計算（メモがある場合155px、ない場合135px）

**実装手順**:
1. メモエリアの背景を描画（別色の矩形）
2. メモテキストを描画（truncate処理を含む）
3. カードの角丸処理（下部はメモエリアと一体化）

#### 5.3 UIコンポーネントの変更

**ファイル**: `src/components/AttendanceList/AttendanceList.jsx`

**変更点**:
1. 各観戦予定カードにメモ入力欄を追加
2. メモの保存処理を実装（リアルタイム保存）
3. メモの表示・編集機能を実装

### 6. データマイグレーション

#### 6.1 既存データへの対応

- 既存のAttendancePlanには`memo`フィールドがないため、`memo: null`として扱う
- 既存データの読み込み時、`memo`フィールドが存在しない場合は`null`として初期化

**マイグレーション処理**:
```javascript
// AttendancePlan.fromJSON()で自動的に処理
static fromJSON(json) {
  return new AttendancePlan({
    ...json,
    memo: json.memo || null  // 既存データの互換性
  })
}
```

---

### 7. 制約事項

#### 7.1 文字数制限

- UIでの入力制限: **20文字**
- データモデルでの制限: なし（ただし、実装時のパフォーマンスを考慮）

#### 7.2 改行の扱い

- 改行は許可しない（1行のみ）
- 改行文字（`\n`, `\r\n`）が入力された場合は、空白文字に置換

#### 7.3 空文字列の扱い

- 空文字列（`""`）は`null`として保存
- 空白のみの文字列も`null`として保存（`trim()`処理）

# Research: サッカー試合予定カレンダーアプリケーション

**Feature**: サッカー試合予定カレンダーアプリケーション  
**Date**: 2026-01-09  
**Status**: Complete

## Technical Decisions

### フロントエンドフレームワーク: ReactJS

**決定**: React 18+ を使用

**理由**:
- ユーザー要件でReactJSの使用が指定されている
- コンポーネントベースのアーキテクチャにより、再利用可能なUI要素を構築できる
- 豊富なエコシステムとコミュニティサポート
- モバイル対応のレスポンシブデザインを実装しやすい

**代替案の検討**:
- Vue.js: 要件でReactが指定されているため除外
- Vanilla JavaScript: 複雑な状態管理が必要になるため、フレームワークを使用

### CSVパーシングライブラリ: PapaParse

**決定**: PapaParse を使用

**理由**:
- 軽量で高性能なCSVパーサー
- ブラウザ環境で動作
- エラーハンドリングが充実
- 非同期処理をサポート
- 日本語文字（UTF-8）の処理に対応

**代替案の検討**:
- csv-parse: Node.js向けで、ブラウザでは使用不可
- 手動パーシング: 複雑なエッジケース（エスケープ文字、改行等）の処理が困難

### データストレージ: localStorage

**決定**: ブラウザのlocalStorage APIを使用してJSON形式でデータを保持

**理由**:
- 要件でNoSQLは使用せず、JSONで保持することが指定されている
- ローカル環境で動作し、インターネット接続不要
- 実装がシンプルで軽量
- ブラウザ標準APIのため追加の依存関係が不要

**制約と対策**:
- 容量制限: 通常5-10MB。1000件の試合予定でも十分な容量
- 同期処理: 大量データの書き込み時にUIがブロックされる可能性があるため、バッチ処理を検討

**代替案の検討**:
- IndexedDB: より大容量だが、要件では不要な複雑さ
- SQLite (WASM): ブラウザで動作するが、要件でJSON保持が指定されているため除外

### 日付操作ライブラリ: date-fns

**決定**: date-fns を使用

**理由**:
- 軽量でモジュール化されている
- 日付のフォーマット、比較、操作が容易
- タイムゾーン対応
- 日本語ロケール対応

**代替案の検討**:
- Moment.js: サイズが大きく、非推奨の方向
- Day.js: 軽量だが、機能が限定的

### ルーティング: React Router

**決定**: React Router v6 を使用

**理由**:
- カレンダー表示、観戦予定一覧、設定画面などの画面遷移が必要
- ブラウザの履歴管理に対応
- シンプルな実装で要件を満たせる

### ビルドツール: Vite

**決定**: Vite を使用（Create React Appの代替）

**理由**:
- 高速な開発サーバーとビルド
- 軽量でモダンな開発体験
- ローカル実行環境での軽量性を重視

### テストフレームワーク: Jest + React Testing Library

**決定**: Jest と React Testing Library を使用

**理由**:
- Reactアプリケーションの標準的なテストスタック
- コンポーネントのユーザー中心のテストが可能
- 統合テストの作成が容易

## CSVフォーマット仕様

**実際のCSVファイル形式**:

```
Group,Round,Date,Kickoff,Home,Away,Stadium,Broadcast
EAST,1,2026-02-06,19:00,横浜Ｆ・マリノス,ＦＣ町田ゼルビア,日産スタジアム,DAZN
WEST,1,2026-02-06,19:00,京都サンガF.C.,ヴィッセル神戸,サンガスタジアム by KYOCERA,DAZN
```

詳細は `contracts/csv-sample.md` を参照してください。

**実装時の考慮事項**:
- 必須フィールド: Date、Kickoff、Home、Away
- オプションフィールド: Group、Round、Stadium、Broadcast
- 日時結合: Date（YYYY-MM-DD）とKickoff（HH:MM）を結合してISO 8601形式の日時文字列を生成
- **特殊値「未定」**: KickoffとStadiumフィールドに「未定」という値が存在する可能性がある
  - Kickoffが「未定」の場合: 日時結合を行わず、`dateTime`は`null`または空文字列として保存。日付のみを保持し、UIでは「未定」と表示
  - Stadiumが「未定」の場合: そのまま保存し、UIでは「未定」と表示
- タイムゾーン: 日本標準時（JST, UTC+9）を想定
- エンコーディング: UTF-8

## パフォーマンス考慮事項

### カレンダー表示の最適化

- 仮想スクロール: 大量の試合予定がある場合、表示される範囲のみをレンダリング
- メモ化: React.memo を使用して不要な再レンダリングを防止
- 日付ごとのグループ化: 試合予定を日付でインデックス化して高速検索

### データ読み込みの最適化

- 遅延読み込み: 必要な日付範囲のみを読み込む
- デバウンス: CSVインポート時の検証処理をデバウンス

## セキュリティ考慮事項

- XSS対策: ユーザー入力（CSVファイル内容）のサニタイゼーション
- ファイルサイズ制限: 過大なCSVファイルのアップロードを制限
- データ検証: インポート前にデータの妥当性を検証

## アクセシビリティ考慮事項

- キーボードナビゲーション: すべての機能をキーボードで操作可能
- スクリーンリーダー対応: 適切なARIA属性の使用
- コントラスト比: WCAG 2.1 AA準拠

## モバイル対応

- レスポンシブデザイン: 画面幅320px以上で適切に表示
- タッチ操作: タップ、スワイプなどのジェスチャーに対応
- パフォーマンス: モバイルデバイスでも滑らかな動作を確保

## 未解決の課題

- CSVフォーマットの詳細仕様: 実装フェーズでユーザーと確認
- エクスポート形式: 観戦予定の一覧出力形式（JSON、CSV、PDF等）の決定
- データ移行: 既存データがある場合の移行方法

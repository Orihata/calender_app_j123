## User Scenarios & Testing *(mandatory)*

### User Story 1 - 試合予定のインポートとカレンダー表示 (Priority: P1)

ユーザーはCSVファイルから試合予定をインポートし、カレンダー形式で日時ごとに複数の試合予定を一括表示できる。

**Why this priority**: これはアプリケーションの基盤機能であり、他のすべての機能がこの機能に依存する。試合予定を表示できない限り、観戦予定の設定やピックアップ機能は意味を持たない。

**Independent Test**: CSVファイルをインポートし、カレンダー上で特定の日時に複数の試合予定が正しく表示されることを確認できる。この機能単体で、ユーザーは試合予定を視覚的に把握できる価値を得られる。

**Acceptance Scenarios**:

1. **Given** ユーザーがCSVファイルを準備している, **When** CSVファイルをインポートする, **Then** 試合予定がシステムに読み込まれ、カレンダーに表示される
2. **Given** 複数の試合予定が同じ日時に存在する, **When** カレンダーでその日時を表示する, **Then** すべての試合予定が一括で表示される
3. **Given** カレンダーが表示されている, **When** 異なる日付を選択する, **Then** その日付の試合予定が表示される
4. **Given** 無効なCSVファイルが提供される, **When** インポートを試みる, **Then** エラーメッセージが表示され、データは読み込まれない

### User Story 2 - 観戦予定の設定 (Priority: P2)

ユーザーは特定の試合を選択して観戦予定としてマークし、観戦予定を管理できる。

**Why this priority**: 試合予定を表示した後、ユーザーが次に必要とするのは観戦する試合を選定することである。この機能により、ユーザーは自分が観戦する予定の試合を明確に管理できる。

**Independent Test**: 試合予定を選択して観戦予定としてマークし、観戦予定一覧で確認できる。この機能単体で、ユーザーは観戦予定を管理できる価値を得られる。

**Acceptance Scenarios**:

1. **Given** カレンダーに試合予定が表示されている, **When** 特定の試合を選択して観戦予定としてマークする, **Then** その試合が観戦予定として記録される
2. **Given** 観戦予定としてマークされた試合が存在する, **When** 観戦予定一覧を表示する, **Then** マークされたすべての試合が表示される
3. **Given** 観戦予定としてマークされた試合が存在する, **When** 観戦予定のマークを解除する, **Then** その試合が観戦予定一覧から削除される
4. **Given** 同じ試合が複数回マークされる, **When** 観戦予定を確認する, **Then** 重複なく1回のみ記録される

---

### User Story 3 - ピックアップ試合の一覧出力 (Priority: P3)

ユーザーは観戦予定としてマークした試合（ピックアップした試合）のみを一覧として出力できる。

**Why this priority**: 観戦予定を設定した後、ユーザーがその情報を他の形式で利用したり、共有したりするために必要となる機能である。すべての試合ではなく、選択した試合のみを出力することで、ユーザーの目的に合った情報を提供できる。

**Independent Test**: 観戦予定としてマークされた試合を一覧として出力し、出力された内容が正しいことを確認できる。この機能単体で、ユーザーは選択した試合情報を外部で利用できる価値を得られる。

**Acceptance Scenarios**:

1. **Given** 観戦予定としてマークされた試合が存在する, **When** 一覧出力を実行する, **Then** マークされた試合のみが一覧として出力される
2. **Given** 観戦予定としてマークされた試合が存在しない, **When** 一覧出力を実行する, **Then** 空の一覧または適切なメッセージが表示される
3. **Given** 複数の観戦予定が存在する, **When** 一覧出力を実行する, **Then** すべての観戦予定が時系列順または指定された順序で出力される
4. **Given** 一覧出力が実行される, **When** 出力形式を確認する, **Then** 試合の主要情報（日時、対戦カード等）が含まれる

### User Story 4 - 待受画面画像出力機能 (Priority: P2)

ユーザーは観戦予定としてマークした試合を、携帯電話の待受画面用の画像として出力できる。

**Why this priority**: 観戦予定を視覚的に管理し、待受画面として活用できることで、ユーザーの利便性が大幅に向上する。

**Independent Test**: 観戦予定一覧から待受画面用画像を生成し、適切な形式（PNG、1080x2400px）で出力できることを確認できる。

**Acceptance Scenarios**:

1. **Given** 観戦予定としてマークされた試合が存在する, **When** 画像出力機能を実行する, **Then** 待受画面用画像（PNG形式、1080x2400px）が生成される
2. **Given** 画像出力が実行される, **When** 画像を確認する, **Then** 観戦予定の試合情報がカード形式で適切に表示される
3. **Given** 背景色が選択可能である, **When** 異なる背景色を選択する, **Then** 画像の背景色が変更される
4. **Given** 51試合を超える観戦予定が存在する, **When** 画像出力を実行する, **Then** 最初の51試合のみが表示される（警告表示）

**詳細仕様**: `docs/feature_spec/wallpaper/WALLPAPER_SPEC_v1.2.0.md` を参照  
**実装バージョン**: Version 1.1.0  
**実装状況**: ✅ 実装完了

### User Story 5 - ひとことメモ機能 (Priority: P2)

ユーザーは観戦予定に対して「ひとことメモ」を追加でき、そのメモは待受画面画像に表示される。

**Why this priority**: 観戦予定に補足情報（メモ）を追加できることで、ユーザーの情報管理が向上する。

**Independent Test**: 観戦予定に対してメモを追加し、そのメモが待受画面画像に表示されることを確認できる。

**Acceptance Scenarios**:

1. **Given** 観戦予定が存在する, **When** メモを入力する, **Then** メモが保存され、観戦予定一覧に表示される
2. **Given** メモが入力されている, **When** 待受画面画像を生成する, **Then** メモがカード下部に表示される
3. **Given** メモ入力欄が空である, **When** 保存する, **Then** メモが`null`として保存される
4. **Given** 20文字を超えるメモを入力しようとする, **When** 入力する, **Then** 20文字までしか入力できない

**詳細仕様**: `docs/feature_spec/MEMO_FEATURE_SPEC.md` を参照  
**実装バージョン**: Version 1.1.0（Version 1.1.2で改善）  
**実装状況**: ✅ 実装完了

### User Story 6 - 試合予定の手動追加機能 (Priority: P3)

ユーザーはCSVファイル以外にも、テキストボックスから手動で試合予定を追加できる。

**Why this priority**: モバイル端末での利用を想定し、CSVファイルがなくても試合予定を追加できるようにする。

**Independent Test**: テキストボックスから試合予定情報を入力し、CSVインポートと同じバリデーション処理で追加できることを確認できる。

**Acceptance Scenarios**:

1. **Given** ユーザーが手動追加画面を開く, **When** 必須情報（日付、キックオフ、ホーム、アウェイ）を入力する, **Then** 試合予定が追加される
2. **Given** 必須情報が不足している, **When** 登録を試みる, **Then** エラーメッセージが表示される
3. **Given** 日付形式が不正である, **When** 登録を試みる, **Then** エラーメッセージが表示される（YYYY-MM-DD形式を要求）

**実装バージョン**: Version 1.1.3  
**実装状況**: ✅ 実装完了

### User Story 7 - 試合予定の削除機能 (Priority: P3)

ユーザーは登録済みの試合予定を削除できる。削除時には関連する観戦予定も自動的に削除される。

**Why this priority**: 誤って登録したデータや不要になったデータを削除できるようにする。

**Independent Test**: 試合予定を選択して削除し、関連する観戦予定も自動的に削除されることを確認できる。

**Acceptance Scenarios**:

1. **Given** 登録済みの試合予定が存在する, **When** 試合予定を選択して削除する, **Then** 試合予定が削除される
2. **Given** 削除対象の試合予定に関連する観戦予定が存在する, **When** 試合予定を削除する, **Then** 関連する観戦予定も自動的に削除される（参照整合性の維持）
3. **Given** 複数の試合予定を選択する, **When** 一括削除を実行する, **Then** 選択したすべての試合予定が削除される

**実装バージョン**: Version 1.1.4  
**実装状況**: ✅ 実装完了

### User Story 8 - 応援クラブ機能 (Priority: P2)

ユーザーは観戦予定に対して、応援するクラブ（home/away）を選択できる。選択したクラブは待受画面画像に反映される。

**Why this priority**: ユーザーが応援するクラブを記録し、視覚的に表現することで、よりパーソナライズされた体験を提供する。

**Independent Test**: 観戦予定に対して応援クラブを選択し、その選択が待受画面画像に反映されることを確認できる。

**Acceptance Scenarios**:

1. **Given** 観戦予定が存在する, **When** 応援クラブ（home/away）を選択する, **Then** 応援クラブが保存される
2. **Given** 応援クラブが選択されている, **When** 待受画面画像を生成する, **Then** 応援クラブが太字で表示され、メモ欄の背景色が応援クラブの色に変更される
3. **Given** 応援クラブが選択されている, **When** 同じクラブを再選択する, **Then** 選択が解除される（トグル機能）

**実装バージョン**: Version 1.1.5（Version 1.1.6で画像出力に反映）  
**実装状況**: ✅ 実装完了

### Edge Cases

- CSVファイルのフォーマットが不完全な場合（必須フィールドが欠落している等）の処理
- 同じ試合がCSVファイルに重複して含まれている場合の処理
- 非常に多くの試合予定（100件以上）が同じ日時に存在する場合の表示方法
- 過去の日付の試合予定がインポートされた場合の扱い
- 観戦予定としてマークした試合がCSV再インポートで削除された場合の処理
- ブラウザのローカルストレージ容量制限に達した場合の処理
- 無効な日時形式（存在しない日付等）がCSVに含まれている場合の処理
- 待受画面画像生成時に51試合を超える観戦予定がある場合の処理（最初の51試合のみ表示）

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: システムはCSVファイルから試合予定をインポートできなければならない
- **FR-002**: システムはインポートされた試合予定をカレンダー形式で表示できなければならない
- **FR-003**: システムは特定の日時に複数の試合予定を一括表示できなければならない
- **FR-004**: システムは試合予定を選択して観戦予定としてマークできなければならない
- **FR-005**: システムは観戦予定としてマークされた試合の一覧を表示できなければならない
- **FR-006**: システムは観戦予定のマークを解除できなければならない
- **FR-007**: システムは観戦予定としてマークされた試合のみを一覧として出力できなければならない
- **FR-008**: システムはデータをローカルのJSON形式で保持しなければならない
- **FR-009**: システムはローカルブラウザ上で動作しなければならない（インターネット接続不要）
- **FR-010**: システムはモバイルデバイスでも可読性の高いフレキシブルなデザインを提供しなければならない
- **FR-011**: システムはCSVインポート時にデータの妥当性を検証しなければならない
- **FR-012**: システムはインポートエラー時にユーザーに分かりやすいエラーメッセージを表示しなければならない
- **FR-013**: システムはCSVフォーマットの詳細仕様を後から定義できる柔軟性を持たなければならない
- **FR-014**: システムは観戦予定としてマークした試合を待受画面用画像（PNG形式、1080x2400px）として出力できなければならない
- **FR-015**: システムは観戦予定に対して「ひとことメモ」（最大20文字）を追加できなければならない
- **FR-016**: システムはテキストボックスから手動で試合予定を追加できなければならない（CSVインポートと同じバリデーション適用）
- **FR-017**: システムは登録済みの試合予定を削除できなければならない（関連する観戦予定も自動削除）
- **FR-018**: システムは観戦予定に対して応援クラブ（home/away/null）を選択できなければならない

### Key Entities *(include if feature involves data)*

- **試合予定 (Match)**: サッカーの試合に関する情報を表す。主要属性として、日時、対戦カード（ホームチーム vs アウェイチーム）、会場、その他の試合関連情報を含む。CSVファイルまたは手動入力から追加され、カレンダーに表示される基本単位。
- **観戦予定 (Attendance Plan)**: ユーザーが観戦する予定の試合を表す。試合予定への参照を持ち、ユーザーが選択した試合のみが観戦予定として記録される。カテゴリ（現地観戦/放送視聴）、メモ、応援クラブなどの追加情報を含む。ピックアップ機能と画像出力機能の対象となる。
- **CSVフォーマット仕様 (CSV Format Specification)**: 試合予定をインポートするためのCSVファイルの構造を定義する。現時点では詳細が未定義だが、システムは柔軟にフォーマット定義を受け入れる設計が必要。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: ユーザーはCSVファイルから100件の試合予定を3分以内にインポートできる
- **SC-002**: ユーザーはカレンダー上で特定の日時のすべての試合予定を1回の操作で確認できる
- **SC-003**: ユーザーは試合予定を選択して観戦予定としてマークする操作を5秒以内に完了できる
- **SC-004**: ユーザーは観戦予定としてマークした試合の一覧を10秒以内に出力できる
- **SC-005**: システムはモバイルデバイス（画面幅320px以上）で試合予定が適切に表示され、スクロールなしで主要情報が確認できる
- **SC-006**: システムはローカル環境でインターネット接続なしで完全に動作する
- **SC-007**: 無効なCSVファイルが提供された場合、ユーザーは30秒以内にエラー原因を理解できる
- **SC-008**: システムは1000件の試合予定を保持しても、カレンダー表示の応答時間が2秒以内である

## Assumptions

- CSVファイルはユーザーのローカルファイルシステムから読み込まれる
- ブラウザのローカルストレージ（localStorage、IndexedDB等）を使用してデータを保持する
- アプリケーションはモダンブラウザ（Chrome、Firefox、Safari、Edgeの最新版）で動作する
- ユーザーは基本的なコンピュータ操作（ファイル選択、クリック等）ができる
- 試合予定の日時はタイムゾーン情報を含むか、システムのデフォルトタイムゾーンを使用する
- CSVフォーマットの詳細仕様は実装フェーズで定義されるが、システムは柔軟にフォーマット変更に対応できる設計とする
